# חותמים – אפליקציית החתמה וניהול משרד למתווכי נדל״ן

אפליקציית ווב מותקנת (PWA) **למובייל בלבד**, בעברית מלאה ומימין לשמאל. המתווך מחתים לקוחות על מסמכי תיווך מהטלפון, הלקוח חותם מקישור בלי להתקין כלום, וכל המשרד מנוהל במקום אחד: לקוחות, נכסים, מסמכים, עסקאות, עמלות וצוות.

התכנון, האפיון וההדמיות נמצאים ב-[`docs/broker-app`](../docs/broker-app).

## מה יש באפליקציה

| תחום | מה עובד |
|---|---|
| כניסה | טלפון + קוד SMS, הרשמה (שם, רישיון תיווך, משרד, חתימה שמורה) |
| תבניות | הזמנת שירותי תיווך · טופס הצגת נכס · הסכם בלעדיות · נספח גילוי נאות (עניין אישי) · שאלון מוכר (גילוי נאות על הנכס) · דף מידע לקונה |

| החתמה | החתמה במקום על הטלפון של המתווך, או שליחה ב-WhatsApp / SMS / קישור · כמה חותמים באותו מסמך · הלקוח ממלא ת״ז וכתובת, מאשר הצהרות, חותם באצבע ומאמת בקוד SMS · מיקום (בהסכמה) |

| שאלון מוכר | בעל הנכס ממלא את השאלון בעצמו בזמן החתימה ← התשובות נשמרות בנכס ← "דף מידע לקונה" נוצר מהן |
| PDF חתום | נוצר כשכולם חתמו: עמוד נספח (אם יש), המסמך, החתימות, ועמוד "תעודת חתימה" (זמנים, טלפון מאומת, IP, מכשיר, מיקום, טביעת תוכן) · נשמרת טביעת SHA-256 של הקובץ |

## הרצה מקומית

דרוש Node.js 22.13 ומעלה (משתמשים ב-SQLite המובנה של Node).

```bash
cd broker-app
npm install
npm run dev          # http://localhost:3000
```

בלי ספק SMS האפליקציה רצה ב**מצב הדגמה**: קודי האימות מוצגים על המסך, והודעות SMS נכתבות ביומן השרת.

בדיקות:

```bash
npm run typecheck
npm test             # בדיקות יחידה (סדר טקסט מימין לשמאל ב-PDF)
npm run build && DATA_DIR=/tmp/e2e npm start &
npm i -D playwright && BASE_URL=http://localhost:3000 npm run e2e   # בדיקת קצה-לקצה בדפדפן במסך טלפון
```

## פריסה לפרודקשן

- שרת Node רגיל או Docker (`Dockerfile` מצורף). הנתונים (מסד SQLite וקבצי PDF חתומים) נשמרים ב-`DATA_DIR` – **חייבים דיסק קבוע ומגובה** (למשל Railway / Render / Fly.io עם volume). Vercel לא מתאים כי אין בו דיסק קבוע.
- משתני סביבה: ראו `.env.example`. חובה: `APP_SECRET`, `APP_URL`, `SMS_WEBHOOK_URL`.
- ספק SMS: `SMS_WEBHOOK_URL` מקבל `POST {to, text, sender}`. אפשר לחבר ישירות ספק ישראלי, או דרך Make/Zapier.
- HTTPS חובה (עוגיות מאובטחות, מיקום, תפריט שיתוף).

## חיבור Google Drive (הגדרה חד-פעמית בשרת)

1. נכנסים ל-[Google Cloud Console](https://console.cloud.google.com/) ויוצרים פרויקט.
2. **APIs & Services → Library** – מפעילים את **Google Drive API**.
3. **OAuth consent screen** – סוג External, שם האפליקציה, מייל תמיכה. ב-Scopes מוסיפים `.../auth/drive.file` (האפליקציה רואה רק קבצים שהיא יצרה – לא את שאר ה-Drive). עד לאישור Google מוסיפים את המיילים של הסוכנים כ-Test users.
4. **Credentials → Create credentials → OAuth client ID** – סוג Web application. ב-Authorized redirect URIs מוסיפים `https://<הדומיין שלכם>/api/google/callback` (ולפיתוח: `http://localhost:3000/api/google/callback`).
5. מעתיקים את Client ID ו-Client secret למשתני הסביבה `GOOGLE_CLIENT_ID` ו-`GOOGLE_CLIENT_SECRET` ומפעילים מחדש.
6. באפליקציה: **עוד → הגדרות → חיבור Google Drive**.

הטוקן של Google נשמר מוצפן (לפי `APP_SECRET`). תקלה ב-Drive לא עוצרת חתימה – היא נרשמת ביומן המסמך ואפשר לשמור שוב ידנית.

בדיקת קצה-לקצה של החיבור מול שרת Google מדומה: `node tests/google-mock.cjs 3200` והרצת האפליקציה עם משתני `GOOGLE_*` שבראש הקובץ, ואז `TEST_DRIVE=1 GOOGLE_API_URL=http://localhost:3200 npm run e2e`.

## מבנה הקוד

```
src/lib/templates.ts   התבניות: שדות, ברירות מחדל, בדיקות, ותוכן המסמך (מקור אחד למסך ול-PDF)
src/lib/pdf.ts         יצירת PDF עם גופן עברי, חתימות ותעודת חתימה
src/lib/bidi.ts        סידור טקסט מימין לשמאל (עברית + מספרים) ב-PDF
src/lib/documents.ts   יצירת מסמך, סגירה כשכולם חתמו, שליחת העתקים, שמירה ל-Drive
src/lib/gdrive.ts      חיבור Google (OAuth) והעלאה ל-Google Drive
src/lib/db.ts          סכמת SQLite
src/app/(app)/…        מסכי המתווך (בית, לקוחות, נכסים, מסמכים, עסקאות, צוות, הגדרות)
src/app/s/[token]      דף החתימה ללקוח (ציבורי, לפי קישור אישי)
src/app/d/[token]      הורדת העתק חתום (ציבורי, 30 יום)
```

## חשוב לפני שימוש עם לקוחות

- **נוסח התבניות הוא טיוטה** שנכתבה לפי דרישות החוק כפי שהן מתוארות במקורות משניים. חובה שעו״ד יאשר כל תבנית, ובמיוחד את הנספח לפי תקנות האתיקה (2024) ואת תקופת שמירת המסמכים.
- סוג החתימה הוא חתימה אלקטרונית (לא "מאושרת" עם תעודה מגורם מאשר). כדאי לברר עם עו״ד אם זה מספיק לכל סוגי המסמכים.
- פרטיות: נשמרים מספרי ת״ז, טלפונים ומיקום. יש להתאים מדיניות פרטיות ואבטחת מידע לתיקון 13 לחוק הגנת הפרטיות.

## מה עוד לא נבנה (שלבים הבאים)

יומן סיורים וסנכרון ליומן Google, הפקת חשבוניות (חשבונית ירוקה / iCount), סריקת ת״ז, כלים מבוססי AI, תשלום ומנוי, אפליקציות בחנויות.
