# אפיון מוצר ותוכנית פיתוח
### "חותמים" (שם עבודה) – החתמה דיגיטלית וניהול משרד למתווכי נדל״ן

**סטטוס:** תכנון – לפני כתיבת קוד · **פלטפורמה:** מובייל בלבד · **שפה:** עברית, RTL מלא

---

## 1. החזון במשפט
המתווך פותח את האפליקציה בסיור, ממלא הזמנת תיווך ב-30 שניות, הלקוח חותם על הטלפון שלו – והעסקה, הלקוח, הנכס והעמלה כבר מנוהלים במקום אחד עד הגבייה.

## 2. הבעיה
| כאב | היום | אצלנו |
|---|---|---|
| הזמנת תיווך לא חתומה = אין זכאות לעמלה | טופס נייר, לקוחות "שוכחים" לחתום | החתמה ב-WhatsApp תוך דקה, עם תזכורות |
| עקיפת מתווך | אין הוכחה מי הציג מה ומתי | טופס הצגת נכס חתום + חותמת זמן + מיקום |
| מידע מפוזר | WhatsApp, אקסל, פנקס, יד2 | כרטיס לקוח/נכס אחד עם כל המסמכים |
| גביית עמלות | מעקב ידני | Pipeline עסקאות + חשבונית בלחיצה |
| ניהול צוות | אין שקיפות | לוח מנהל: חתימות, סיורים, עסקאות לכל סוכן |

## 3. קהל יעד ופרסונות
1. **אבי, מתווך עצמאי (45)** – עובד לבד, 90% מהזמן בשטח. צריך מהירות ופשטות.
2. **מיכל, מנהלת משרד (38)** – 6 סוכנים. צריכה שליטה, תבניות אחידות, דוחות ועמלות.
3. **דניאל, סוכן מתחיל (27)** – רוצה מערכת שתגיד לו מה לעשות היום.
4. **הלקוח החותם** – קונה/מוכר/שוכר. לא מתקין כלום, פותח קישור וחותם. חייב לעבוד על כל טלפון.

## 4. מתחרים (השערות עבודה – לאימות במחקר)
| קטגוריה | דוגמאות | החוזק שלהם | הפער שאנחנו תוקפים |
|---|---|---|---|
| החתמה למתווכים (ישראל) | חתימה טובה | ממוקד בהחתמה למתווכים, עברית | ניהול משרד מקצה לקצה, עסקאות ועמלות |
| CRM למתווכים (ישראל) | מערכות CRM ייעודיות לתיווך | ניהול נכסים ולקוחות | חוויית מובייל, החתמה מובנית |
| החתמה כללית | DocuSign, Adobe Sign, SignNow | אמינות, Audit Trail | לא מותאם לחוק המתווכים, עברית חלקית, יקר |
| נדל״ן בחו״ל | dotloop, SkySlope | Transaction management | לא קיים בישראל – מודל השראה |

**מיצוב:** "המהירות של החתמה טובה + העומק של CRM – בתוך הטלפון."

## 5. מפת פיצ'רים ותעדוף

### MVP (שלב 1 – החתמה) – 10–12 שבועות
- הרשמה ב-SMS OTP, פרופיל מתווך (מס' רישיון, לוגו, חתימה שמורה)
- **ספריית תבניות מוכנות לפי חוק המתווכים**: הזמנת שירותי תיווך (מכירה/קנייה/שכירות), הסכם בלעדיות, טופס הצגת נכס, ביטול בלעדיות
- אשף יצירת מסמך ב-3 צעדים: תבנית → נכס+לקוח → שליחה
- שליחה ב-WhatsApp / SMS / קישור; **החתמה במקום** על הטלפון של המתווך ("מסור ללקוח")
- **החתמה קבוצתית בסיור** – כמה קונים על אותו טופס הצגה
- דף חתימה ללקוח (Web, ללא התקנה): קריאה, מילוי ת״ז, חתימה ביד, אישור OTP
- Audit Trail: חותמת זמן, IP, מכשיר, מיקום (בהסכמה), Hash ל-PDF + תעודת חתימה בעמוד האחרון
- סטטוסים בזמן אמת (נשלח / נצפה / נחתם) + תזכורות אוטומטיות
- ארכיון מסמכים עם חיפוש
- **העתק חתום ושמירת PDF** (ראו סעיף 5א)
- **ספריית תבניות מוכנות:** הזמנת שירותי תיווך, הסכם בלעדיות, גילוי נאות ומידע על הנכס, שאלון מוכר נכס (ראו `templates/`)
- כרטיס לקוח וכרטיס נכס בסיסיים (נוצרים אוטומטית מהמסמך)

### 5א. העתק חתום ושמירת PDF (חלק מה-MVP)
תקנות האתיקה מחייבות למסור ללקוח עותק ולשמור מסמכים, ולכן זה פיצ'ר ליבה ולא תוספת.
- **שליחת העתק אוטומטית:** מיד כשהחותם האחרון חותם, PDF חתום נשלח לכל החותמים (WhatsApp / SMS / מייל, לפי מה שיש בכרטיס) ולמתווך. אפשר לכבות או לשנות בהגדרות.
- **שליחת העתק ידנית:** מכל מסמך חתום – בחירת נמענים (חותמים, בעלים נוסף, עו״ד, מנהל המשרד, כל איש קשר) וערוץ (WhatsApp, SMS, מייל, קישור להעתקה). כל שליחה נרשמת ביומן הפעולות.
- **שמירת PDF:** הורדה למכשיר (קבצים / גלריה), שיתוף דרך תפריט השיתוף של הטלפון, וגיבוי אוטומטי אופציונלי ל-Google Drive / OneDrive / Dropbox בתיקייה לפי נכס או לקוח.
- **מבנה הקובץ:** שם קובץ קבוע `{סוג מסמך}_{כתובת}_{שם לקוח}_{תאריך}.pdf`; העמוד האחרון הוא "תעודת חתימה" (זמנים, טלפון שאומת, IP, מכשיר, מיקום, קוד אימות של הקובץ).
- **קישור מאובטח:** הלקוח מקבל קישור להורדה (בתוקף 30 יום, ניתן לחידוש) במקום קובץ גדול. אפשר להגדיר סיסמה = 4 ספרות אחרונות של ת״ז.
- **אימות מסמך:** דף ציבורי שבו אפשר להעלות PDF ולבדוק שלא שונה מאז החתימה.
- **שמירה בארכיון:** כל מסמך חתום נשמר לפחות 7 שנים (לאשר מול עו״ד את תקופת השמירה הנדרשת), ואי אפשר למחוק מסמך חתום – רק לסמן כמבוטל.

### V2 (שלב 2 – ניהול משרד) – 10 שבועות
- לידים: קליטה ידנית / טופס / ייבוא אנשי קשר, תיוג, התאמת נכס-לקוח (Matching)
- יומן סיורים ופגישות + סנכרון Google/Apple Calendar
- Pipeline עסקאות (ליד → סיור → מו״מ → זכ״ד → חוזה → עמלה שולמה)
- עמלות: חישוב לפי % / סכום, חלוקה בין סוכנים, תזכורות גבייה
- חשבוניות דרך אינטגרציה (חשבונית ירוקה/Morning, iCount)
- צוות: הזמנת סוכנים, הרשאות (מנהל/סוכן/מזכירה), תבניות משרדיות נעולות
- דשבורד מנהל ודוחות

### V3 – מבדלים
- OCR לתעודת זהות (מילוי אוטומטי)
- AI: כתיבת מודעה מתמונות הנכס, סיכום שיחה, "מה לעשות היום"
- מעקב עקיפה: התראה כשנכס שהוצג נמכר (לפי נתוני עסקאות)
- חתימה אלקטרונית מאושרת (תעודה מגורם מאשר) למסמכים רגישים
- פורטל לקוח: קונה רואה את כל הנכסים שהוצגו לו

## 6. מפת מסכים (Sitemap)
```
כניסה ── OTP ── Onboarding (רישיון, לוגו, חתימה)
טאב בר (5): בית · לקוחות · [＋ החתמה] · נכסים · עוד
├── בית: סיכום היום, מסמכים ממתינים, סיורים, פעולות מהירות
├── לקוחות: רשימה + סינון → כרטיס לקוח (מסמכים, נכסים שהוצגו, עסקאות, היסטוריה)
├── ＋ החתמה (אשף): בחירת תבנית → פרטים → חותמים → תצוגה → שליחה / החתמה במקום
│     └── מסמך חתום: סטטוס → שליחת העתק / שמירת PDF / אימות
├── נכסים: רשימה/מפה → כרטיס נכס (תמונות, בלעדיות + תוקף, סיורים, מתעניינים)
└── עוד: מסמכים · יומן · עסקאות · עמלות · צוות · תבניות · הגדרות
דף לקוח (Web): פתיחה → קריאה → פרטים → חתימה → OTP → אישור + PDF
```

## 7. User Flow מרכזי – הזמנת תיווך בסיור
1. ＋ → "טופס הצגת נכס"
2. בחירת נכס (או הוספה מהירה: כתובת + מחיר) → הוספת קונים (שם + טלפון; אנשי קשר מהטלפון)
3. שדות חובה לפי התקנות ממולאים אוטומטית (פרטי מתווך, רישיון, דמי תיווך ברירת מחדל)
4. "החתמה במקום" → הטלפון עובר ללקוח → חתימה → הקונה הבא
5. PDF חתום נשלח לכל קונה ב-WhatsApp, נשמר בכרטיס הנכס ובכרטיס כל לקוח, ונפתח ליד בכל לקוח

**יעד:** פחות מ-60 שניות מפתיחת האפליקציה עד חתימה.

## 9. ארכיטקטורה מומלצת
| שכבה | בחירה | נימוק |
|---|---|---|
| אפליקציית מתווך | React Native + Expo (TypeScript), RTL מאולץ | iOS + Android מקוד אחד, גישה למצלמה/אנשי קשר/Push |
| דף חתימה ללקוח | Next.js קל (Web, ללא התקנה) | נפתח מקישור WhatsApp בכל טלפון |
| Backend | Supabase (Postgres + Auth OTP + Storage + RLS) באזור EU | מהיר לפיתוח, הפרדת משרדים ברמת DB |
| PDF | pdf-lib בצד שרת (Edge Functions) + פונט עברי (Heebo/Rubik) | הטמעת חתימה + עמוד תעודה |
| הודעות | WhatsApp Business Cloud API + ספק SMS ישראלי | ערוץ ההפצה העיקרי בישראל |
| חשבוניות | API של חשבונית ירוקה / iCount | לא לבנות הנהלת חשבונות |
| ניטור | Sentry + PostHog | שגיאות + מדדי Activation |

**אבטחה:** הצפנת ת״ז ברמת שדה, טוקן חד-פעמי עם תפוגה לכל חותם, Hash SHA-256 לכל PDF חתום, יומן פעולות בלתי ניתן לעריכה, גיבוי יומי, עמידה בתיקון 13 לחוק הגנת הפרטיות.

## 10. עיצוב (Design System)
- **צבעים:** כחול-נייבי `#1E2A5A` (אמון), טורקיז `#14B8A6` (פעולה), ענבר `#F59E0B` (ממתין), ירוק `#16A34A` (נחתם), רקע `#F5F7FB`
- **טיפוגרפיה:** Rubik לכותרות, Heebo לטקסט, מינימום 16px בשדות קלט
- **מובייל בלבד:** כפתור פעולה ראשי באזור האגודל, טאב בר תחתון, Bottom Sheets במקום מודאלים, יעדי לחיצה ≥ 44px
- **נגישות:** ניגודיות AA, תמיכה בהגדלת טקסט, תוויות לקורא מסך

## 12. מודל עסקי (הצעה ראשונית, לאימות מול תמחור מתחרים)
- **חינם:** 5 מסמכים בחודש

## 13. מדדי הצלחה
- Activation: חתימה ראשונה תוך 24 שעות מההרשמה ≥ 60%
- זמן ממוצע משליחה לחתימה < 15 דקות
- Retention חודש 3 ≥ 70%
- 20+ מסמכים לסוכן בחודש
